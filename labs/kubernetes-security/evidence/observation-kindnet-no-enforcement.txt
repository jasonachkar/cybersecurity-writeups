One-off observation (NOT reproducible by script). Recorded by hand from a manual
experiment on 2026-11-05 on the same VM as the scripted runs; nothing below is
regenerated by scripts/run-cluster-lab.sh.

Cluster: kind v0.33.0, node image kindest/node:v1.37.0, default CNI (kindnet).
kindnet image: docker.io/kindest/kindnetd:v20260820-69b56db7
Host kernel: 6.18.44 (the sandbox VM).

Test: busybox server pod + busybox client pod in one namespace, `wget` from client to server.
  before any NetworkPolicy ........................ reachable (HTTP body "ok", exit 0)
  after a default-deny Ingress+Egress NetworkPolicy . reachable (HTTP body "ok", exit 0)
  30 seconds after the policy ...................... reachable (HTTP body "ok", exit 0)
The NetworkPolicy object was accepted by the API server. Nothing enforced it.

kindnet log (kube-network-policies controller), abbreviated:
  "Starting controller" name="kube-network-policies"
  "Policy engine is ready."
  "syncing nftables rules" ... error= conn.Receive: netlink receive: no such file or directory
  "initial nftables sync failed" err= conn.Receive: netlink receive: no such file or directory

Interpretation (likely, not proven): this VM kernel does not support the nftables
operations kindnet's policy controller uses, so the controller could not program
any rules. On a kernel with full nftables support kindnet may enforce policy; the
lab therefore installs Calico and runs scripts/np-smoke.sh before trusting any
network result. The same default-deny test under Calico v3.33.0 timed out as
expected (see np-smoke.json).
